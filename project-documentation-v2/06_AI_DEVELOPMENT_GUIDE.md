## 🛑 2. قائمة الممنوعات الصارمة والخطوط الحمراء (Strict Anti-Patterns)

1. **ممنوع كسر العزل الأمني للطلاب (Zero-Trust Student Isolation):**
   * ❌ يُمنع منعاً باتاً طلب أو قبول `section_id` أو `grade_id` من الطالب عبر `req.params` أو `req.query` أو `req.body`.
   * ✔️ يجب استخراجهما حصراً من التوكن المفكك (`req.user.sectionId` و `req.user.gradeId`).

2. **ممنوع التوسع خارج نطاق V1 (Zero Scope Creep):**
   * ❌ يُمنع إضافة جداول أو حقول أو صفحات لميزات مستقبلية (مثل بوابات الدفع، تتبع الحضور المعقد، أو إشعارات SMS).

3. **ممنوع كسر التوافقية الهجينة لقواعد البيانات (Cross-Driver Safety):**
   * ❌ يُمنع كتابة استعلامات SQL مخصصة لمحرك واحد وتفشل في الآخر (مثل دوال خاصة بـ MySQL فقط أو SQLite فقط).
   * ✔️ استخدام استعلامات ANSI SQL القياسية المعلمة (`?`) المتوافقة مع المحول في `backend/config/db.js`.

4. **ممنوع استخدام أطر تنسيق خارجية غير معتمدة:**
   * ❌ يُمنع فرض TailwindCSS أو مكتبات UI ثقيلة ما لم يطلب المستخدم ذلك صراحة.
   * ✔️ الالتزام بتنسيقات الـ Vanilla CSS النظيفة، خط `SF Arabic`، ومكونات الـ iOS و SaaS المعتمدة.

## 💻 3. معايير كتابة الأكواد (Code Style & Engineering Standards)

### 3.1 معايير الواجهة الأمامية (Frontend Guidelines):
* استخدام `Vue 3` بنمط `Composition API` وحصراً وسم `<script setup>`.
* استخدام المتغيرات التفاعلية `ref()` و `computed()` و `onMounted()`.
* عرض المواد الدراسية باستخدام الأيقونات المجسمة ثلاثية الأبعاد المعتمدة (3D Claymorphism Icons):
  * 📐 الرياضيات (`math_3d.jpg`)
  * 🔬 العلوم العامة (`science_3d.jpg`)
  * 🕌 التربية الإسلامية (`islamic_3d.jpg`)
  * 🔤 اللغة الإنجليزية (`english_3d.jpg`)
  * 📖 اللغة العربية (`arabic_3d.svg`)
  * 💻 الحاسوب والتقنية (`computer_3d.svg`)
  * 🌍 الدراسات الاجتماعية (`social_3d.svg`)
* التعامل مع المودلز والنوافذ المنبثقة عبر المكونات المشتركة `ShadcnDialog` و `ShadcnDrawer`.

### 3.2 معايير الخادم والبرمجيات الخلفية (Backend Guidelines):
* كل مسار يجب أن يكون محمياً بـ `authenticateToken` وفحص الصلاحية `requireRole(...)`.
* الالتزام بصيغة الاستجابة الموحدة:
  ```json
  // نجاح:
  { "success": true, "data": { ... }, "message": "..." }

  // خطأ:
  { "success": false, "message": "رسالة الخطأ باللغة العربية الواضحة" }
  ```
* معالجة الأخطاء دائماً داخل بلوكات `try / catch` وإرجاع كود الحالة المناسب (`400`, `401`, `403`, `404`, `500`).

## ✅ 4. بروتوكول التحقق قبل إنهاء المهام (Definition of Done)

قبل إبلاغ المستخدم بانتهاء أي مهمة تطويرية:
1. **التحقق من عدم وجود أخطاء تجميع (Build Check):** تشغيل `npm run build` في مجلد `frontend/` والتأكد من خلوه من الأخطاء.
2. **فحص الروابط النسبية (Relative Links Check):** التأكد من أن جميع الروابط في الوثائق نسبية (`./...` أو `../...`) ولا تحتوي على مسارات نظام مطلقة (`file:///...`).
3. **تطابق الميزات (Traceability Check):** التأكد من أن التعديل يطابق تماماً ما هو موثق في ملفات `Rest-api/` و `project-documentation-v2/`.
