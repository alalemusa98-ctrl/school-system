## 3. الميزات الوظيفية — داخل V1 أم خارجها؟ (Feature Boundary Matrix)

### ✅ داخل V1 — المعتمد للبناء الفوري

#### أ. المصادقة والأمان (Auth & Security):
- [x] بوابة دخول موحدة `/login` بتبويب 3 أدوار
- [x] توليد وفحص JWT مع Payload مخصص لكل دور
- [x] وسيط `authenticateToken` و `requireRole`
- [x] تشفير كلمات المرور بـ `bcryptjs` (10 Salt Rounds)
- [x] عزل شعبة الطالب من التوكن — لا من العميل

#### ب. واجهة الطالب (Student — Read-Only):
- [x] الملف الشخصي: الاسم والصف والشعبة

- [x] الامتحانات: قائمة الاختبارات المجدولة

- [x] الجدول الأسبوعي: 30 حصة مع أسماء المعلمين
- [x] المواد: قائمة مواد الصف مع معلمي الشعبة

#### ج. واجهة المعلم (Teacher — CRUD لمهامه فقط):
- [x] عرض التكليفات الأكاديمية المسندة
- [x] إنشاء واجب (`HOMEWORK`) أو امتحان (`EXAM`) لشعبة واحدة

- [x] جدول الحصص الشخصي للمعلم

## 4. قواعد حماية حدود V1 (Boundary Enforcement Rules)

```
[قاعدة 1 — Zero Scope Creep]
أي مطوّر أو Prompt للـ AI يطلب ميزة غير موجودة في قائمة ✅ أعلاه
→ الرد الفوري: "هذه الميزة خارج نطاق V1 — راجع MVP_BOUNDARY.md"

[قاعدة 2 — No DB Schema Additions]
لا يُضاف أي جدول أو حقل جديد لقاعدة البيانات في V1
→ جداول V1 محددة ومجمدة بـ 10 جداول فقط (DATABASE_DESIGN.md)

[قاعدة 3 — Single Section per Task]
كل مهمة في V1 تستهدف شعبة واحدة فقط
→ حقل section_id واحد في assessment_tasks (لا مصفوفة)

[قاعدة 4 — Immediate Model Answers Only]
has_solution = 1 → يظهر الحل فوراً بدون موعد مجدول
→ حقل publish_at غير موجود في V1
```
