# الدليل الشامل للمستخدمين ومصفوفة الصلاحيات (Master Users & RBAC Permissions Matrix)

يقوم النظام على نموذج صلاحيات ثلاثي صارم وقائم على الأدوار (**Role-Based Access Control - RBAC**)، يضمن فصل المهام، أمان البيانات، ومنع التداخل أو تسريب المعلومات بين الطلاب والمعلمين والإدارة.

## 2. التفصيل الوظيفي لكل دور (Role Capabilities & Boundaries)

---

### 👑 1. مدير النظام / الإدارة (`ADMIN`)
* **الدور في المنظومة:** المسؤول الأعلى عن ضبط الهيكل التعليمي، تسجيل الطلاب والمعلمين، وتوزيع نصاب التدريس، وبناء الجداول الأسبوعية.
* **بيانات الدخول:** اسم المستخدم (`username`) + كلمة المرور الإدارية المشفرة (`password_hash`).
* **الصلاحيات التنفيذية:**
  * **الاسترجاع والقراءة (Read):** الوصول لكافة إحصائيات المدرسة، سجلات جميع الطلاب بجميع الفصول، قائمة المعلمين، الهيكل الأكاديمي، وجداول الحصص لكافة الشعب.
  * **الإنشاء (Create):** إضافة سنوات دراسية، صفوف (1-9)، شعب دراسية، مقررات، تسجيل طلاب جدد، إنشاء حسابات المعلمين بكلمات مرور مشفرة بـ `Bcrypt`، وإسناد التكليفات.
  * **التعديل والنقل (Update):** نقل الطلاب بين الشعب، تعديل أرقام الجلوس أو الأسماء، واستبدال وتحديث حصص الجدول الأسبوعي بنمط `Upsert`.
  * **الحذف (Delete):** حذف الصفوف، الشعب، المواد، سجلات الطلاب، حسابات المعلمين، التكليفات، وتفريغ الحصص (مع تطبيق سياسات الحذف التتابعي `CASCADE`).

---

### 👨‍🏫 2. المعلم (`TEACHER`)
* **الدور في المنظومة:** المسؤول الأكاديمي عن نشر وإدارة الواجبات والامتحانات والحلول النموذجية المعتمدة ومتابعة جدول حصصه الشخصي.
* **بيانات الدخول:** اسم المستخدم (`username`) + كلمة المرور الخاصة به (`password_hash`).
* **الصلاحيات والقيود:**
  * **الاسترجاع والقراءة (Read):** استعراض قائمة الفصول والمواد المسندة إليه رسمياً من الإدارة، قائمة المهام التي أنشأها بنفسه، وحصصه الخاصة في الجدول الأسبوعي.
  * **الإنشاء والنشر (Create):** نشر واجبات (`HOMEWORK`) أو امتحانات (`EXAM`) للشعب والمواد المسندة إليه فقط، مع رفع المرفقات (حتى 10MB)، وتفعيل وإرفاق الحل النموذجي المعتمد (نص + ملف).
  * **التعديل (Update):** تعديل نصوص، تواريخ، أو مرفقات المهام التي يملكها شخصياً فقط (`WHERE teacher_id = req.user.id`).
  * **الحذف (Delete):** حذف الواجبات والامتحانات المنشورة بواسطته فقط.
  * **القيود الصارمة (Strict Boundaries):**
    * حظر النشر لأي شعبة أو مادة غير مسندة له بجدول `teacher_assignments` (إرجاع `403 Forbidden`).
    * حظر الوصول أو التعديل على مهام المعلمين الآخرين.
    * حظر تعديل الهيكل المدرسي أو سجلات الطلاب.

---

### 🎒 3. الطالب وولي الأمر (`STUDENT`)
* **الدور في المنظومة:** المستفيد النهائي؛ يمتلك واجهة استعراضية فائقة السرعة والجمال البصري (iOS-Style) تمنحه الشفافية الكاملة لكل ما يخص شعبته.
* **بيانات الدخول:** رقم الجلوس (`roll_number`) + كود الطالب السري الخاص (`student_code`).
* **الصلاحيات والقيود:**
  * **نمط الصلاحية العام:** للقراءة فقط (**Read-Only**).
  * **الاسترجاع والقراءة (Read):**
    * **الملف الشخصي:** بيانات القيد الشخصية، الصف، والشعبة.
    * **الواجبات والحلول:** استعراض واجبات شعبته فقط مجمعة بالأيام، تنزيل المرفقات، وفتح الحل النموذجي المعتمد فور توفره (`has_solution = 1`).
    * **الامتحانات:** جدول الاختبارات الشهرية والنماذج الاسترشادية.
    * **الجدول الأسبوعي:** جدول حصص شعبته الـ 30 وأسماء المعلمين المخصصين.
    * **المواد:** قائمة مواد صفه مع أسماء أساتذة فصله وتصفية المهام حسب المادة.
  * **القيود الصارمة (Strict Isolation):**
    * تطبيق مبدأ **عزل المستأجر الصارم (Zero-Trust)** باستخراج `sectionId` من التوكن المفكك في الخادم وحجب فصول الآخرين.
    * لا يملك أي صلاحيات للكتابة أو التعديل أو الحذف في قاعدة البيانات.

## 4. بنية التوكن وحقن الصلاحيات (JWT Token Claims Structure)

```json
// توكن المشرف العام (ADMIN)
{ "id": 1, "role": "ADMIN", "username": "admin" }

// توكن المعلم (TEACHER)
{ "id": 2, "role": "TEACHER", "username": "teacher2", "fullName": "أ. أحمد سالم" }

// توكن الطالب (STUDENT)
{ "id": 1, "role": "STUDENT", "rollNumber": "1001", "fullName": "أحمد خالد المصراتي", "gradeId": 5, "sectionId": 1 }
```

## 5. الحواجز الأمنية لمنع اختراق الصلاحيات (Security Guardrails)

1. **حظر التصعيد الأفقي والرأسي (Privilege Escalation Prevention):**
   * يفحص وسيط `requireRole` رتبة المستخدم في كل طلب؛ فيتم رفض محاولة أي طالب أو معلم استدعاء مسارات `/api/admin/*` فورياً بكود `403 Forbidden`.
2. **الحماية التلقائية للبيانات في الواجهة الأمامية:**
   * يتحقق حارس المسارات `router.beforeEach` من التوكن المحفوظ في `localStorage` قبل تحميل أي شاشة؛ فإذا حاول مستخدم فتح واجهة لا تطابق دوره، يُعاد توجيهه تلقائياً إلى لوحته الرئيسية.
3. **حماية ملكية الموارد (Resource Ownership Check):**
   * عند قيام المعلم بتعديل أو حذف مهمة، يفرض الاستعلام شرط الأمان: `WHERE id = ? AND teacher_id = req.user.id` لمنع التلاعب بمهام الزملاء.
